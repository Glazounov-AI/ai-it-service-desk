# F3.6-A — Ticket draft model and builder

The existing TS-022 and system prompt define the draft contract. TicketDraft retains those fields and adds session identity, case revision, evidence, actions, completeness and timestamps. The builder requires an escalated matching session and validates routing against the local CSV, KB references and evidence links. No LLM, database writes or external submission are performed. IDs and timestamps are generated per build; idempotency belongs to F3.6-B.

D18: completion of a collection action does not prove that resource names were collected. VPN RESOURCE_ACCESS drafts conservatively flag missing resource names until typed collection is implemented. troubleshooting_completed means the configured actions were reported completed without resolution, not that all information was collected. is_complete reflects currently implemented missing-information rules only. The safety filter is reapplied to the draft; it is not a guarantee against all secrets. The repository must validate evidence ownership in F3.6-B.

TS-022 single-turn retrospective action recognition is not implemented by this builder; it requires workflow integration and evidence validation. No changes to the existing Decision Engine, API or storage in this package. Preliminary regression: 118 tests passed on Python 3.13.5; target validation on Python 3.14.4 remains required.
