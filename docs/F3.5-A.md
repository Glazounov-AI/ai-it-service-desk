# F3.5-A — Diagnostic Case foundation

Baseline: Service Desk 2e7742f. SQLite additive migration; existing sessions and messages remain unchanged. One case per session, lazily persisted. Session status remains authoritative. Optimistic revision checks reject stale writes. User evidence is stored before the external consultation, so it survives upstream consultation failure. Evidence references an exact sanitized user message in the same session; assistant messages cannot serve as evidence. Unsafe and out-of-scope turns are excluded.

GET /sessions/{session_id}/diagnostic-case exposes the development case snapshot. Like existing session endpoints it is not authorized for public use. Existing sessions are not retroactively populated. The case stores user reports verbatim, not verified technical facts or extracted atomic facts. Category/subcategory are classifier hypotheses. Actions, resolution, routing and KB fields are placeholders for F3.5-B; no action completion is inferred. Existing consultation and state transitions remain unchanged. Case and assistant response are separate transactions. Evidence grows with session length; retention and bounded context remain future work.

Local regression: 105 passed using Python 3.13.5 in the build environment; target Python 3.14.4 verification required. No live provider calls. No new dependencies or RAG changes.
