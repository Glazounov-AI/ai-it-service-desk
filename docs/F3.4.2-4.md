# F3.4.2–F3.4.4 — deterministic classification and safety

Taxonomy and priority are loaded from routing-table.csv; KB availability is
based on the KB CSV, not retrieval results. Rules live in config/*.json.
Classification is additive to the existing response and stored in message metadata.
No support group assignment, state transitions or ticket creation are performed.
Safety filtering precedes message persistence and upstream requests. Recognized
unsafe input receives a local warning. Validation errors omit raw input.

This is a preliminary rule set, not exhaustive coverage of the 28 taxonomy pairs.
Confidence values are heuristic, not calibrated probabilities. Ambiguous and
out-of-scope classifications are metadata only; normal requests still reach RAG
for compatibility. Decision enforcement is deferred to subsequent stages.
Regex filtering cannot guarantee detection of every secret. Existing histories
are not migrated. Context and LLM classification are not implemented here.
Production deployment requires additional safety and authorization testing.
