# F3.3 — Сессии и история

Целевая версия Python: 3.14.4. Новых зависимостей нет.
Запуск из корня: `python -m uvicorn service_desk.api:app --host 127.0.0.1 --port 9992`.
SERVICE_DESK_DB_PATH по умолчанию data/service_desk.db (относительно рабочей директории).

POST /sessions {"user_id":"demo"} → 201, id, status=new.
GET /sessions/{id} → состояние.
POST /sessions/{id}/messages {"query":"VPN"} → ответ RAG.
GET /sessions/{id}/messages → упорядоченная история с метаданными.
POST /sessions/{id}/close → closed. Неизвестная сессия: 404; закрытая или занятая: 409.
/consult остаётся без изменений. При ошибке RAG сохраняется только сообщение пользователя.

SQLite: отдельные короткие транзакции, внешние ключи, UTC, индекс истории.
Переходы проверяются в repository.transition; автоматические переходы кроме закрытия
не реализованы. История пока не передаётся в RAG: запросы обрабатываются независимо.
Защита от параллельных запросов действует в одном процессе/цикле событий; запускать с одним worker.
Нет авторизации, user_id не подтверждён, API только локальный. История содержит исходный текст,
поэтому не вводить секреты или реальные персональные данные до реализации защиты.
Нет пагинации, политики хранения, идемпотентности и миграций схемы; доработка перед production.
Повтор после ошибки создаёт новое сообщение. При аварии между запросом и записью ответа
может остаться сообщение без ответа. SQLite синхронный, рассчитан на локальный MVP.

Проверка: `python -m pytest -q`. Реальная интеграция и Python 3.14.4 проверяются на целевой машине.
